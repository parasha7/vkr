# ПРИЛОЖЕНИЕ Г. ДОКУМЕНТАЦИЯ НА РАСШИРЕНИЕ «LASERCONTROL»

Версия прототипа: 0.1.0 · Дата документации: 20.11.2026 · Статус: прототип, требует технического теста

## Г.1. Общие сведения

Расширение «LaserControl» предназначено для среды mBlock 5 и обеспечивает управление лазерным гравером ACMER S1 через контроллер-посредник. Дидактическая функция расширения — скрыть от учащегося 9 класса низкоуровневый G-код GRBL и предоставить набор визуальных блоков, оперирующих понятиями «точка», «перемещение», «мощность», «фигура», «остановка».

**Поддерживаемое оборудование:** ACMER S1 (диодный лазер 450–455 нм, поле 130 × 130 мм, контроллер GRBL, скорость обмена 115200 бод). Использование очков для CO₂-лазера 10,6 мкм недопустимо; требуется OD≥4 в диапазоне 445–455 нм [29–31, 34].

**Платформа разработки:** mBlock 5 Extension Builder (live mode), API `app`, `device`, `block` [32, 33]. Прошивка контроллера — C++ (Arduino IDE), библиотека ArduinoJson 6.x [35].

## Г.2. Техническое задание

**Назначение:** программный мост «визуальный блок → JSON-команда → G-код GRBL».

**Пользователь:** ученик 9 класса (через блоки) и учитель (через инструкцию по установке и чек-лист безопасности).

**Функциональные требования:** палитра из 13 блоков; проверка границ рабочего поля; блоки аварийного останова; установка мощности и скорости; построение линий, прямоугольника и окружности; запрос состояния.

**Нефункциональные требования:** скорость обмена 115200 бод; задержка между отправкой команды и ответом не более 4 с; отказ при некорректном JSON; передача ответа в среду mBlock в виде JSON; работа в live-режиме без прошивки пользовательского кода в гравер.

**Ограничения:** точность позиционирования определяется гравером; окружность аппроксимируется 24 отрезками; проверка границ программная и не заменяет аппаратную кнопку; совместимость с конкретной сборкой mBlock 5 подтверждается тестом.

### Г.2.1. Палитра блоков

| № | Визуальный блок | Поля | JSON-команда | Действие GRBL |
|---|---|---|---|---|
| 1 | подключиться к граверу | — | `{"cmd":"connect"}` | `$I`, ответ `Ready` |
| 2 | вернуться в ноль | — | `{"cmd":"home"}` | `G28` |
| 3 | переместить в точку | X, Y | `{"cmd":"move","params":{"x":50,"y":50,"abs":true}}` | `G1 X50.00 Y50.00 F…` |
| 4 | сдвинуть на | ΔX, ΔY | `{"cmd":"move","params":{"x":10,"y":0,"abs":false}}` | `G1` с пересчётом координат |
| 5 | лазер вкл/выкл | on/off | `{"cmd":"laser","params":{"state":"on"}}` | `M3 S…` / `M5` |
| 6 | установить мощность | 0–100 % | `{"cmd":"power","params":{"value":20}}` | `M3 S51` |
| 7 | установить скорость | мм/мин | `{"cmd":"feedrate","params":{"value":1000}}` | параметр `F` |
| 8 | линия | X1, Y1, X2, Y2 | `{"cmd":"line","params":{…}}` | две команды `G1` |
| 9 | прямоугольник | X, Y, W, H | `{"cmd":"rect","params":{…}}` | пять команд `G1` |
| 10 | окружность | X, Y, R | `{"cmd":"circle","params":{…}}` | 24 команды `G1` |
| 11 | пауза | мс | `{"cmd":"delay","params":{"ms":1000}}` | задержка в прошивке |
| 12 | АВАРИЙНАЯ ОСТАНОВКА | — | `{"cmd":"emergency_stop"}` | `!`, `0x18`, `M5` |
| 13 | состояние гравера | — | `{"cmd":"status"}` | JSON с координатами и состоянием |

## Г.3. Архитектура

```text
mBlock 5 + LaserControl  ── JSON (USB, 115200) ──►  контроллер-посредник
        ▲                                              │ (парсинг, checkBounds, G-код)
        └──────────── JSON-ответ ◄───────────────────────┘
                                                        │
                                                        ▼
                                        ACMER S1 (GRBL) ──► заготовка
```

Последовательность выполнения команды:

1. Ученик перетаскивает блок в рабочую область и задаёт параметры.
2. `index.js` формирует JSON-строку и отправляет её через `device.writeRaw` [32].
3. Прошивка считывает строку до символа перевода строки, разбирает JSON через ArduinoJson.
4. Выполняется проверка границ: `0 ≤ X ≤ 130`, `0 ≤ Y ≤ 130`.
5. Формируется строка G-кода и отправляется в `Serial1` (GRBL).
6. Прошивка ожидает ответ `ok` / `error` не более 4 секунд и отправляет JSON-ответ в mBlock.
7. mBlock выводит ответ в окно отладки; при ошибке блок не продолжает выполнение цепочки.

Применение платы с двумя UART обосновано: Arduino UNO имеет один аппаратный последовательный порт, а программная эмуляция второго на 115200 бод делает разбор JSON ненадёжным. Рекомендуются Arduino Mega 2560 или ESP32.

## Г.4. Протокол обмена

| Поле | Тип | Назначение |
|---|---|---|
| `cmd` | string | Имя команды upper-level |
| `params` | object | Параметры команды (координаты, мощность, задержка) |
| `status` | string | `ok`, `info`, `error` |
| `message` | string | Человекочитаемое пояснение |
| `x`, `y` | number | Текущие координаты в мм |
| `feed` | number | Текущая подача, мм/мин |
| `laser` | string | `on` / `off` |

Пример обмена:

```text
SENT mBlock->Arduino: {"cmd":"move","params":{"x":50,"y":50,"abs":true}}
SENT Arduino->GRBL: G1 X50.00 Y50.00 F1000
RCVD GRBL: ok
RCVD Arduino->mBlock: {"status":"ok","message":"Move completed","x":50,"y":50,...}
```

Команда останова использует команды GRBL `!` (быстрый останов) и `0x18` (Ctrl+X, software reset), затем `M5`. Команда `M112`, встречавшаяся в раннем черновике, относится к прошивке Marlin и в GRBL не поддерживается.

## Г.5. Реализация клиентской части

Исходный код: `code/LaserControl/index.js`, паспорт расширения — `code/LaserControl/manifest.json`.

Клиентская часть описывает 13 блоков в формате Extension Builder и реализует обработчик `onRun`, который сопоставляет opcode блока с JSON-командой. Ответ считывается в обработчике `onRead` через `device.readText(false)` и выводится в окно отладки. При нажатии красной кнопки mBlock вызывается `onStopAll`, отправляющий `emergency_stop`.

Ключевой фрагмент:

```javascript
onRun(args, app, device, block) {
    switch (block.opcode) {
        case 'moveAbsolute':
            return this.sendCommand(app, device, {
                cmd: 'move',
                params: {x: Number(args.X), y: Number(args.Y), abs: true}
            });
        case 'emergencyStop':
            return this.sendCommand(app, device, {cmd: 'emergency_stop'});
        // … остальные блоки
    }
}
```

## Г.6. Реализация прошивки

Исходный код: `code/LaserControl/firmware/lasercontrol.ino`.

Прошивка использует `Serial` для связи с компьютером и `Serial1` для GRBL. Основные функции: `processJson`, `cmdMove`, `cmdLaser`, `cmdPower`, `cmdRect`, `cmdCircle`, `cmdEmergencyStop`, `inBounds`, `sendGrbl`.

Ключевой фрагмент проверки границ:

```cpp
bool inBounds(float x, float y) {
    return x >= 0.0f && x <= FIELD_X && y >= 0.0f && y <= FIELD_Y;
}
```

Преобразование процентов мощности в S-значение GRBL:

```cpp
int powerToS(int percent) {
    if (percent < 0) percent = 0;
    if (percent > 100) percent = 100;
    return static_cast<int>((percent * 255L) / 100L);
}
```

## Г.7. Инструкция по установке и калибровке

1. Установить Arduino IDE и библиотеку ArduinoJson 6.x.
2. Подключить TX1/RX1 контроллера к RX/TX гравера; `Serial` — к USB компьютера.
3. Загрузить прошивку **до подключения лазерного модуля**.
4. В mBlock 5 открыть Extension Builder, импортировать `manifest.json` и `index.js`.
5. Выбрать COM-порт платы, скорость 115200 бод.
6. Проверить ответ `Ready` и выполнить холостую программу: `home → move (10;10) → laser off → home`.
7. Проверить калибровку: нанести тестовую линию 50 мм и измерить штангенциркулем. Допуск ±1 мм.
8. Только после успешных проверок перейти к гравировке на заготовке.

## Г.9. Ограничения и доработки

1. Палитра не покрывает импорт произвольного SVG «одной командой» — контур задаётся последовательностью координат или через подготовленный скрипт.
2. Окружность аппроксимируется отрезками; для точной геометрии требуется поддержка G2/G3.
3. Проверка границ не защищает при неверной установке начала координат оператором.
4. Требуется подтверждение совместимости с конкретной версией mBlock 5.
5. Дальнейшая доработка — локализация сообщений об ошибках и журнал команд в интерфейсе ученика.
